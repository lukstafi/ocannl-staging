Shape schemes (gh-ocannl-404)

The low-level, explicit layer of shape schemes, which the %op integration (gh-ocannl-1751) wraps. A scheme is the shape constraints a tensor function imposes, inferred once by a trace and instantiated at each application:

  • a shape error inside the function that does not depend on its arguments' shapes is raised by Scheme.trace, at the definition;
  • Scheme.instantiate adds the scheme's constraints, renamed, relating it to given argument and result shapes, without running the function: the shapes close as an inline application of the function would have closed them.

What is shared and what is per-application follows ML's value restriction: the dimensions of a tensor created before the trace -- a shared parameter, lifted to the function's unit-parameter scope -- stay fixed across applications, and everything the function creates (its intermediates, a parameter created inside it, a capture reference made inside it) is fresh per application. So create the shared parameters before Scheme.trace. The design note is the gh-ocannl-404 issue's reconciled-plan comment; docs/shape_inference.md has the summary.

type tensor := t
type t
val label : t -> Base.string
val arity : t -> Base.int
val num_results : t -> Base.int
val trace : label:Base.string -> Base.int -> (tensor Base.list -> tensor Base.list) -> t

trace ~label n f applies f to n tracing tensors whose shapes are fresh row variables, inside with_rewind, and returns the scheme of the constraints it registered over them and over its results (a flat list: flatten a structure). The trace leaves nothing in the session. Raises Row.Shape_error prefixed "tracing the shape scheme <label>: " on a shape error in f (including one only the end-of-trace check of f's trailing Shape.set_dim and the like finds), when f forces dims or projections (inference cannot close during a trace), and for what a scheme cannot carry: a precision-dependent total-elements constraint (random number generation inside f), or a capture reference made outside f and bound or set by it.

val instantiate : ?application:Base.string -> t -> args:Shape.t Base.list -> results:Shape.t Base.list -> Base.unit

instantiate s ~args ~results adds s's constraints for one application of its function to args with results (fresh, inferred shapes, or the shapes of tensors computing the results), without running the function. An argument-dependent shape error raises Row.Shape_error prefixed "applying the shape scheme <label> to <application>: " and taints the session, as a failed construction does; the constraints carry the application's name, so a failure at the closure names it too. The next closure applies the solution to args and results and closes them. Valid across closures, unless the scheme depends on open state no shape it used holds (then refused after a closure: trace again).

Automatic schemes of %op functions (gh-ocannl-1751)

%op gives a function a scheme when every parameter of the function it returns is a tensor parameter (docs/syntax_extensions.md says which qualify). The closure built at the () application -- or, for a function without a () stage, its first application -- traces the scheme; each application then checks the scheme against its arguments' shapes, in a window that is always rewound, before the body runs and registers as it always does. A shape error that does not depend on the arguments raises at the trace, prefixed "tracing the shape scheme <function>: "; one that does raises at the application, before the body runs, prefixed "applying the shape scheme <function> to <arguments>: ". A trace a scheme cannot carry (random number generation, an external capture reference, forcing dims, or a body that cannot run on tracers) leaves the function unschemed, as it was before, once its rewind succeeded. Ids are unaffected: traces and checks allocate tensor ids, node uids and shape-variable ids from reserved ranges.

val check_definition : name:Base.string -> (Base.unit -> Base.unit) -> Base.string Base.list

check_definition ~name (fun () -> ignore (block conf ())) runs a trial application of a %op block definition inside a window that is always rewound and allocates no session ids, so the () traces of the block and of the sub-blocks it builds run, and with them any shape error that does not depend on the arguments, prefixed "checking the definition <name>: ". Returns the labels of the schemes traced, innermost first; the session is unchanged afterwards. It catches errors that hold for every configuration and those of the trial configuration only; it costs the trial's construction and traces. Prefer it to a bare block conf (), which leaves the trial's parameters in the session.
