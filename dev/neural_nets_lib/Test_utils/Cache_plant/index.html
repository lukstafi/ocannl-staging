Module Test_utils.Cache_plant

Planting schedule-cache entries by hand from a few named arguments, and the waiver for claims resting on cache I/O the filesystem refused.

Planting schedule-cache entries by hand, and waiving the claims a cache operation rests on where the filesystem refused it.

A test that needs an entry the tuner no longer writes (a corrupt or stale winner, a fissioned winner built from a chosen segmentation, a synthetic entry for a pure-filesystem exercise) builds it here rather than spelling out the Ir.Schedule_cache.entry record, so a field added to the entry reaches every planted one through these defaults. Every entry built here records no default-pipeline measurement, tensorized best, default fingerprint or search trajectory: the shape of an entry written before those fields existed, which replays as "nothing is known".

The backend name is an explicit argument wherever a key or a codegen tag is derived (as Ir.Schedule_cache.codegen_tag takes it), never read off the limits record.

key ~backend ~timing_identity ~limits ~capabilities canon is the key Autotune.tune looks canon's routine up under, from the compiling context's timing identity, limits and codegen capabilities; None without a concrete timing identity.

val plant : ?saved:??? -> ?segments:??? -> ?best_ms:??? -> ?baseline_ms:??? -> cache_dir:Base.string -> backend:Base.string -> timing_identity:Ir.Backend_intf.timing_identity Base.option -> limits:Ir.Backend_intf.hardware_limits -> capabilities:Ir.Backend_intf.codegen_capabilities -> SC.canonical -> SC.cache_io Base.list

plant ~cache_dir ~backend ~timing_identity ~limits ~capabilities canon stores, under key, an entry for canon's routine self-described the way Autotune.tune describes one it stores (the codegen tag and timing objective of this process, canon's digest), carrying saved and segments. Returns the store's cache I/O (SC.recording_cache_io): what a claim resting on the planted entry is waived by (unless_refused). Without a concrete timing identity the key is None, nothing is stored, and the record is empty.

The cache-I/O refusal waiver

The cache absorbs a filesystem refusal by design (gh-ocannl-1040): a refused store or lookup leaves a claim about a store or a replay false for a reason none of its own predicates observes. Such a claim is waived, as an environment skip and never as a pass, where an operation it rests on was refused. A deterministic refusal (a rejected filename, a commit that always fails) would waive it on every run, so a test using the waiver also keeps one claim no refusal waives: not every store it attempted was refused.

val refused : SC.cache_io -> bool

Whether the filesystem refused the operation.

val refused_on : string

The waiver's skip reason.

val refused_in : SC.cache_io Base.List.t -> string -> Base.bool

refused_in ios label: whether any of ios was refused, naming on stderr, for the claim label it waives, what refused and why.

val unless_refused : SC.cache_io Base.List.t -> Base.String.t -> Base.bool -> Base.unit

unless_refused ios label b claims b where none of ios was refused, and skips label as an environment skip (refused_on) where one was.
