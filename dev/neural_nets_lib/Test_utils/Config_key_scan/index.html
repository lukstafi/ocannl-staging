Module Test_utils.Config_key_scan

Scanning OCaml sources for the config keys they read, shared by the configuration-consistency tests.

Scanning OCaml sources for the configuration keys they read.

Shared by the two consistency tests that hold the configuration honest: test_config_consistency (every key documented and registered) and digest_completeness (every key classified against the cache identity, gh-ocannl-572). Both need the same fact — which keys a source file reads — so they read it the same way.

val keys_in_source : Base.String.t -> Base.String.t Base.List.t

The arg_name literals of the get_global_arg / get_global_flag calls in content. Two forms appear in the codebase: ~arg_name:"key" (direct call sites) and ?(arg_name = "key") (optional parameter defaults, e.g. get_style in tnode.ml).

val keys_in_files : Base.string Base.List.t -> (Base.String.t, Base.String.comparator_witness) Base.Set.t

keys_in_source over each file, as a set. Call sites only — this is what test_config_consistency means by "every key a source file asks for is documented and registered".

val settings_keys_in_source : Base.String.t -> Base.String.t Base__List.t

The other spelling of a configuration read: a field of the startup-resolved Utils.settings record, whose field names are the config keys, and the two predicates over it that fold in the log_level > 1 threshold (debug_log_from_routines, with_runtime_debug). A census built from arg_name literals alone would miss every one of these — large_models is read as Utils.settings.large_models in the codegen, so a future misclassification of it could pass unchallenged (Codex P2 on PR #337).

val keys_by_file : Base.string Base.List.t -> (string * (Base.String.t, Base.String.comparator_witness) Base.Set.t) Base.List.t

Every configuration read of a file — arg_name call sites and settings_keys_in_source — keyed by file basename, for tests that care where a key is read. Field names that are not config keys come along; callers intersect with the registry.
